Week 1 · Chiavenna, Data Analysis

What a model is, and how one row of the table works

In this course a model is not decoration. It is a short picture of reality. Later you will read a coefficient off that picture.

On the first slide Chiara Chiavenna defines a model as a simplified and meaningful description of reality. Simplified, because you cannot write a whole customer down. Meaningful, because the picture keeps what the decision needs: who this person is, what you did to them, and what they did back.

Keep thisThe slide says these classes do not add separate exam topics. They exist so that, on the written exam, you can read a statistical output. Do not skip week 1 because it feels “too basic”.

What you need before a model

You need a table. In the course that table is a Portuguese bank campaign: 4,521 customers and 17 columns. One uploaded file is called bank-3, the other bank. The cells match. Only the technical wrapper of the file differs.

Read the slide’s four words as a sentence, not as jargon.

Word on the slideIn plain EnglishIn the bank file
RowOne unit you observed. Here, one customer the campaign contacted.For example: age 30, unemployed, married, balance 1787, answer y = no.
ColumnOne characteristic, measured the same way for everyone.age, job, balance, duration, y.
CellThe value where that row and that column meet.This customer’s balance is 1787 euros.
Empty cellThe value is missing. Missing is not zero.The slide asks you to ask why: not collected, the person refused, or lost in processing.

One row, said as a person

Take the first row of the notebook and ask “what do we know about this customer?”

  • age = 30, job = unemployed, marital = married, education = primary. That is the portrait.
  • default = no, balance = 1787, housing = no, loan = no. That is money and credit.
  • contact = cellular, day = 19, month = oct, duration = 79 seconds, campaign = 1. That is how this contact went.
  • pdays = −1, previous = 0, poutcome = unknown. This person was not contacted before, in this database. Minus one is a code for “there was no previous contact”. It is not “the contact lasted minus one day”. In describe() the median of pdays is −1 for that reason.
  • y = no. The customer did not accept the bank’s offer. If you later model “who will say yes”, this is the outcome, the dependent variable.
On the examYou will not be asked to build a model in software. The closing class says software is not needed. You will be asked what is Y, what is X, and whether those X’s let you draw a conclusion.

A worked miniature

Question. The balance cell is empty. An intern wants to type 0, “so the model does not break”. May they?

  1. Zero means “the account holds zero euros”. An empty cell means “we do not know”.
  2. This file already contains real zeros. Some customers have balance = 0. Some have a negative balance, down to −3,313. Zero is already taken by a meaning.
  3. If you write 0 in place of a blank, you mix “we do not know” with “there is no money”. The average balance then lies.
  4. First ask why it is blank. The slide gives three working versions: the information was never collected, the customer refused, or the value was lost in processing.
