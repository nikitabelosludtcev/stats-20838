Week 4 · Lab_1_ArteaCase

The Artea notebook, step by step

The notebook repeats the slides. Below are only the lines you need in order to explain the conclusion. Colouring a chart at length does not earn a mark.

Notebook. Lab_1_ArteaCase. It repeats the Artea solution slides. Read it for the commands, and take the rounded exam numbers from the slides.

import pandas as pd
import statsmodels.formula.api as smf
db_artea = pd.read_excel('DataArtea.xlsx')
db_artea.head()
db_artea.shape

head() shows the first rows, so you can check that the columns are there. shape prints (5000, 14) in one run: five thousand people. In another printout the screen shows 15 columns, because the instructor’s file already contains a ready-made channel field and interaction_Insta_Coup. That does not change the logic of the test. If you do not have a ready-made interaction, you build it yourself: a 1 only when both Instagram and the coupon equal 1.

desc = ['num_past_purch', 'spent_last_purchase', 'weeks_since_visit',
        'browsing_minutes', 'shopping_cart', 'channel_Facebook',
        'channel_Instagram', 'channel_Referral', 'channel_Other']
db_artea.groupby("test_coupon")[desc].mean()

groupby("test_coupon") cuts the table into coupon and no coupon. mean() computes the mean of each column inside each piece. That is step 1.

group1 = db_artea[db_artea['test_coupon'] == 0]['num_past_purch']
group2 = db_artea[db_artea['test_coupon'] == 1]['num_past_purch']
t_stat, p_value, df = smws.ttest_ind(group1, group2, alternative='two-sided', usevar='pooled')

Square brackets with a condition keep only the rows you want. == compares. ttest_ind compares two means. alternative='two-sided' is a two-sided test, as with age in week 1: you care about a difference in either direction. pooled uses a shared spread. The print: t = −0.99, p = 0.3208.

For the Facebook share they use proportions_ztest, because the column is 0/1 and the question is about a share, not about “average height”. The notebook has a small mess: the z-test print uses the variable t_stat left over from the previous test, so −0.99 appears on the screen again, while the p-value is already the new one, 0.3298. On the exam, if you see that, say: look at the p-value of this test, not at a name that was reused by accident.

model = smf.ols(formula='trans_after ~ test_coupon', data=db_artea).fit()
print(model.summary())

smf.ols builds an OLS. The formula reads “trans_after depends on test_coupon”. Y is on the left, X is on the right. fit() estimates the coefficients. summary() prints the table: coefficient, standard error, t, p-value, R². For revenue you change only the left-hand side: revenue_after ~ test_coupon.

model = smf.ols(
    formula='trans_after ~ test_coupon + num_past_purch + spent_last_purchase + weeks_since_visit + browsing_minutes + shopping_cart + channel_Facebook + channel_Instagram + channel_Referral + channel_Other',
    data=db_artea).fit()

The plus signs add controls. The coupon coefficient is now “holding the rest of this list fixed”. Because of randomization it stays around +0.03.

Later the notebook builds an interaction. The meaning of trans_after ~ test_coupon * shopping_cart + ...: in a statsmodels formula the star asks for the variables themselves and for their product. That is not ordinary multiplication of numbers in Python. The confusion is common. In arithmetic * multiplies. In a model formula * also adds the interaction.

What you should be able to explain with the notebook closedgroupby().mean() checks balance. ols("Y ~ test_coupon") gives the average effect. The p-value on the coupon coefficient decides whether that effect differs from zero. A star inside the formula adds an interaction.
